# Prompt failures

Every model-facing wording that exists because a model got it wrong, one line
each: the constant (or symbol) that carries the wording, the date, the model, and
what it did. The wording itself lives in code; this is the record CLAUDE.md's
"Prompt text is code" invariant asks for. Add a line when a wording changes for
a failure; never delete one, the failure is still the reason.

| Symbol | Observed | Failure |
|--------|----------|---------|
| `REFERENCES_NOTE` (`llm/adapters/openai_wire.py`) | before 2026-09-19, 7.5B model | Handed four TypeScript declarations for tools already in its list, it wrote a program to call them three runs out of three; nothing had said the list changed. Anthropic's API expands `tool_reference` blocks itself; an OpenAI-compatible endpoint cannot, so this sentence does the telling. |
| `DenoRunner._unanswered` error text (`sandbox/deno.py`) | before 2026-09-19, 4B model | A script called `main();` without `await`, returned at once, and the reply to the in-flight call met a closed pipe; "handler is closed" told the model nothing and it gave up. Told only "must be awaited", it deleted the `main();` line and shipped four scripts that declared `main` and never called it, so the text names the fix: `return await main();`. |
| `PRUNED` (`session/compaction.py`) | before 2026-09-19 | A model told only "[cleared]" asked the person what the tool had said, so the placeholder says to call the tool again. |
| `INSTRUCTION` (`agent/compaction/prompt.py`) | before 2026-09-19 | "Do NOT mention": a model that sees a summarization request in its history otherwise opens its next reply with "as summarized above". "Output only the checkpoint": tools are not offered on this request, but a model that writes `execute_typescript(` in prose is still a summary that cannot be used. |
| `NO_PROGRESS_WARNING`, `NO_PROGRESS_REFUSAL` (`agent/hooks/native/no_progress/hook.py`) | 2026-09-13, 12B model | Ran the identical program twice, received the identical result twice, and with nothing telling it the second was the first again, answered with an invented address instead of the next tool. |
| `DETAILS_DESCRIPTION` (`tools/native/code/prompts.py`) | before 2026-09-19 | "callable directly" is the sentence that turns reading a schema into selecting the tool; without it the model reads the types and then writes a program for a single call, a script per step: every cost of code mode and none of its saving. |
| `EXECUTE_DESCRIPTION` (`tools/native/code/prompts.py`) | before 2026-09-19, 7.5B model | The opening used to be "Write ONE script that does the whole task", the strongest imperative in the request, and the model obeyed it over the system prompt's "only when it saves round trips" every time; it now says what a program is for first. "ONE script" stays for the batch case because a model given a code tool otherwise calls it once per tool; the return/log rule keeps intermediate values out of the conversation. The `main()` sentence: the model wrapped its steps in `async function main()` and ended with `main();`, the body returned at once, the shim exited, and the reply in flight met a dead pipe, twice in two runs. |
| `CODE_PROMPT` (`tools/native/code/prompts.py`) | before 2026-09-19, 7.5B model | Separate from the tool descriptions because a model decides what it is capable of before it reads any of them. The earlier wording made a program the only route, and measured against offering every tool directly it lost on every axis at 17 tools (docs/mcp-tool-scaling.md §6): a sequential task became a script per step. "Call it directly" for one call and "a program" for many is Anthropic's own guidance, and what a 7.5B model could do where writing a correct program was beyond it. |
| `NOTHING_CAME_BACK` (`tools/native/code/tools.py`) | before 2026-09-19, 4B model | "Finished without printing anything" was read as success four times in a row by a model that had declared `main` and never called it; the report that followed had invented figures. The text states the consequence, not the observation. |
| `LOCATION_TOOL.description` (`tools/native/location/tool.py`) | 2026-09-16 | The trigger words are the point: a model not told when to reach for this answers "I don't know where you are" instead of asking. "Read the catalog" is there because, told only to "pass the coordinates to a places search", a model wrote a script calling `places__search`, a name it guessed, and reported the failure as the answer. Every client tool is in `DEFAULT_TOOLS` for the same reason: a model not shown `get_location` answers "I don't know where you are" instead of asking. |
| `_DESCRIPTION` (`skills/tool.py`) | before 2026-09-19 | "before starting" exists because a model shown the tool would otherwise use it after it had already answered from general knowledge; the skill is meant to change how the task is done, not the reply's afterword. The last sentence exists because a public skill's body may say "run scripts/extract.py", and a model with no shell must be told that the instructions, not the scripts, are what it has. |
| `CODE_PROMPT` appended to the system prompt (`web/agent.py`) | before 2026-09-19 | A model shown three unfamiliar tools and not told what they are for answers "I can't do that" rather than discover its own capabilities, so the prompt travels with the tools. |
| `FETCH_DESCRIPTION` (`mcp-servers/instagram/.../tools/descriptions.py`) | before 2026-09-19 | "in ONE call" plus the ten-vs-two sentence: the MCP connection serves one call at a time (`backend/harness/mcp/connection.py` `_serve`), so a per-URL loop pays full round-trip latency per reel and `Promise.all` does not help; nothing in the signature implies it. "never fails the others ... or abandoning the batch": a model shown one `unavailable` item stops and reports total failure. "a caption very often names it outright": measured, two live reels carried "📍 @natalinaitalian" and "📍 Rajgad Fort" before any frame was decoded. |
| `READ_DESCRIPTION` (`mcp-servers/instagram/.../tools/descriptions.py`) | before 2026-09-19 | The Warung Mak Cik and Jalan Telawi examples are verbatim observed ASR output; a general "transcripts may be inaccurate" did not stop the model spelling a venue's name from audio, two concrete misreadings did. "none (... many reels carry only music)": a music-only reel transcribed as "bira bira bira bira", so `speech: "none"` is asserted by the server and the parenthetical stops the model retrying it as a fault. "it never names a place": without it the vision model volunteered a venue and a confidence and two models disagreed with no audit trail. "Weight the evidence in this order": the model trusted a fluent transcript over a terse, correct on-screen overlay. |
| `SEARCH` (`mcp-servers/markets/.../tools/descriptions.py`) | before 2026-09-19 | "not by a ticker you have guessed": Yahoo lists Maybank as 1155.KL (and separately MAYBANK.KL), and 'BTC' matches bitcoin, bitcoin-cash and a dozen tokens on CoinGecko; without the sentence the model passed MAYBANK straight to get_quote and read not_found as "no such company". |
| `QUOTE` (`mcp-servers/markets/.../tools/descriptions.py`) | before 2026-09-19 | "Prices are DELAYED": stale data presented as current; `as_of` is on every result and this sentence is what makes the model read it. |
| `HISTORY` (`mcp-servers/markets/.../tools/descriptions.py`) | before 2026-09-19 | "choose the interval for the range": a year of daily bars is ~250 rows of JSON the session log re-sends every turn; the sentence stops the model hitting the cap and asking again with the same arguments. |
| `PROFILE` (`mcp-servers/markets/.../tools/descriptions.py`) | before 2026-09-19 | "must be reported as unavailable, never estimated" and "already percentages": the two numeric failures the finance-LLM literature records most, filling a gap with a plausible figure and the 0.367 vs 36.7 unit mix-up. |
| `FINANCIALS` (`mcp-servers/markets/.../tools/descriptions.py`) | before 2026-09-19 | "full units, NOT millions" and "single quarters, not cumulative": Yahoo returns raw units where filings print millions, and the model has both conventions in its training data. |
| `FILINGS` (`mcp-servers/markets/.../tools/descriptions.py`) | before 2026-09-19 | "The document text is not returned": stops the model promising to read a 10-K it cannot open. |
| `NEWS` (`mcp-servers/markets/.../tools/descriptions.py`) | before 2026-09-19 | "do not infer a story's content from its title": in an early run a headline about earnings became a paragraph about their contents. |
| `SEARCH_DESCRIPTION` (`mcp-servers/places/.../tools/descriptions.py`) | before 2026-09-19 | "Send a CLEAN query" and the nasi-lemak example: Google's docs say Text Search is "not intended for ambiguous queries"; one non-indexed descriptor took a working query to 0 results, and without the paragraph the model pasted the whole reel description in. "An @handle ... makes an excellent query": a live caption's "📍 @natalinaitalian" was the venue's real name. "there is no API that can add a place to their saved list": stops the model offering to save it (My Maps write API gone since 2011, `place/add` since 2018). |
| `DETAILS_DESCRIPTION` (`mcp-servers/places/.../tools/descriptions.py`) | before 2026-09-19 | "only after you have settled on a single candidate": Place Details is a higher-tier SKU than Text Search, so fanning it out is the expensive mistake; "don't" alone left the model calling details anyway, so the last sentence gives it something to do instead. |
| `SYSTEM_PROMPT` memory sentence (`web/agent.py`) | 2026-09-19, gemma-4-e4b (LM Studio) | A model with a memory server in the catalog and nothing telling it what the server is for has no reason to search before answering about the person's past; the sentence names the functions and the two moments, before answering about an earlier conversation and when asked to remember. |
| `remember` step 0 (`.agents/skills/remember/SKILL.md`) | 2026-09-19, gemma-4-e4b (LM Studio) | Told "read the four functions with `get_function_details` first" in the `find-place` wording, the model called `memory__write_note` directly, was refused, and reported "I have successfully saved the information!" with nothing on disk. The step now gives the exact `get_function_details` call, says the refusal is what a skipped call looks like, and the answer rule says a save is reported only when the result carried a `file_path`. On the next run the model still tried the direct call first, but followed the refusal to the schema read and the note was written. |
| `EMPTY_REPLY_NOTE` (`agent/hooks/native/empty_reply/hook.py`) | 2026-09-20, gemma-4-e4b (LM Studio) | After a mid-turn compaction, handed the summary and a search result that held the answer, the model returned one token and no text, and the loop closed the turn as completed with an empty bubble. The note names both ways out (words, or the tool) because a model told only "answer now" after a tool step may call the same tool again; one note per turn, then the turn fails with `EMPTY_REPLY`. |
| `DENIED_RESULT` (`tools/approval.py`) | 2026-09-20, 4B model | Told "the user denied this call, so it did not run", the model read a refusal as a tool fault and answered "there was an issue with the call" after re-reading the skill for a way round it. The text now names the button, says it is a decision and not a fault, and says what to tell the person. |
| `_DESCRIPTION` scripts sentence (`skills/tool.py`) | 2026-09-23, ilmu-glm-5.1 | Asked to create a skill with a script and run it, the model saved a SKILL.md telling itself to call `unit_convert__convert`, a function no tool provides, for a script file it had no way to write, then retyped the script into `execute_typescript`. The sentence now says a TypeScript file under scripts/ is a program, not a function to call by name, and how to run it; "Any other script cannot run" keeps the earlier row's failure fixed, since a Python script still has no shell. |
| `_WRITE_FILE_DESCRIPTION` (`tools/native/skills/tools.py`) | 2026-09-23, ilmu-glm-5.1 | Same run: the program it wrote for the skill failed to parse the first time. The description states the only shape `execute_typescript` runs, the body of an async function that ends with `return` and has no imports or exports, because a script under scripts/ is run by passing its text as that code. |
| unclosed-frontmatter message in `_split` (`skills/models.py`) | 2026-09-23, ilmu-glm-5.1 | The model opened a SKILL.md with `---`, put the instructions inside the frontmatter and never closed it; `skill_save` answered "SKILL.md must start with a `---` YAML frontmatter block", which was false for that text, and the model never found the fix and went on to claim the skill was saved. The message now names the missing closing `---` and where the instructions go. |
